# 项目全景台（Cockpit）

> **一句话**：把 git、代码、文档三个来源交叉验证后，回答一个 03-TASKS.md 回答不了的问题——
> **「文档说完成的功能，生产分支 master 上真的有吗？」**

- 生成器：`scripts/gen-cockpit.mjs`
- 产物：`outputs/cockpit.html`（看板）、`outputs/ask/*.md`（询问 AI 的上下文包）
- 版本：v1
- 重建耗时：约 1.6 秒

---

## 一、为什么需要它

`docs/STATUS.md` 只读 `03-TASKS.md` 的人工勾选。那个口径回答的是「某个分支上写完了没有」，
不是「能不能用」。NAS 生产只部署 `master`，所以两者的差距就是这个项目的真实风险。

全景台引入两个**客观证据层**，让进度不再只是一句声明：

| 证据层 | 来源 | 回答什么 |
|--------|------|---------|
| git | 分支领先/落后、`git ls-tree`、`git show master:<文件>` | 这个功能在不在生产分支上 |
| 代码 | 控制器 `@GetMapping/@PostMapping` 注解、前端 `client.get/post/...` 调用 | 这个功能到底做没做、增删改查齐不齐 |
| 文档 | `03-TASKS.md` 勾选、`05-CHANGELOG.md`、`docs/superpowers/plans/` | 人是怎么记录它的（仅作对照） |

三者不一致的地方，就是看板要报红的地方。

## 二、怎么用

```bash
node scripts/gen-cockpit.mjs     # 重建
open outputs/cockpit.html        # 打开（离线可用，零 CDN 依赖）
```

安装 git 钩子后（提交 / 合并 / 切换分支自动重建）：

```bash
sh scripts/install-hooks.sh
```

> 钩子源码在版本化的 `.githooks/`，安装时复制到 `.git/hooks/`。
> **刻意不使用 `core.hooksPath`**：本仓库的 `.git/hooks/prepare-commit-msg` 是 lefthook 生成的 shim，
> 改 hooksPath 会让它失效。

### 打开前自动同步（推荐日常使用）

**双击项目根目录的 `打开看板.command`。**

它会先把看板重建到当前工作区的最新状态，再打开浏览器——所以你每次点开拿到的都是最新的，
不会看到上一次生成的旧快照。

> 首次双击如果被 macOS 拦下，右键 → 打开，允许一次即可。

命令行等价物：

```bash
sh scripts/open-cockpit.sh     # 先重建，再打开
```

| 方式 | 行为 |
|------|------|
| `打开看板.command` / `sh scripts/open-cockpit.sh` | 先同步到最新，再打开（日常用这个） |
| `node scripts/gen-cockpit.mjs` | 只重建，不开浏览器 |
| `open outputs/cockpit.html` | 只打开现有文件，**可能已过期** |
| git 钩子 | 提交 / 合并 / 切换分支后自动重建 |

钩子负责「保持文件新鲜」，`.command` 负责「打开前一定是最新」。两者不冲突，装了钩子也建议用 `.command` 打开。
重建失败时脚本会明确报错并且**不会打开旧版本看板**。

## 三、九个页面各看什么

| 页面 | 用途 |
|------|------|
| 一眼总览 | KPI、风险清单、三端进度、**模块 × 证据矩阵**（文档说的 vs 代码有的） |
| 进展 | 与「上一次打开」和「7 天前」相比变了什么；任务完成数趋势 |
| 架构图 | 四层架构，**边框颜色就是生产状态**（蓝实线=已在 master，黄虚线=只在分支，灰虚线=仅规划） |
| 模块功能地图 | 每个模块的任务进度与功能分组；点卡片下钻 |
| 接口与 CRUD | 26 个资源 × 增/删/改/查/业务动作 × BE/PC/MB，外加未上线接口清单 |
| 规划与在途 | 方案按证据分档：进行中 / 待上线 / 规划中 / 已完成；未完成任务按模块归组 |
| 分支地图 | 分支领先落后、改动范围、可删/该合并/该保留建议 |
| 里程碑 / 文档导航 | CHANGELOG 抽取的时间线；48 篇文档分级与过期标记 |

**下钻**：点任意模块卡片或证据矩阵行 → 弹出详情面板，含逐资源的 CRUD 矩阵、接口明细（未上线的标黄）、任务明细、相关页面、最近提交。

## 四、进展是怎么来的（历史快照）

看板每次生成时会顺手把十几个关键指标写成一个几 KB 的 JSON：

```
outputs/cockpit-history/
├── 2026-09-15.json    # 一天一份，用于「与 7 天前相比」和趋势图
└── last-run.json      # 每次打开都覆盖，用于「与上一次打开相比」
```

下次生成时读上一份做减法，就得到「进展」页上的所有数字。**纯文件，不起服务，不联网。**

设计上刻意保持最小侵入：

- 一天只有一份日期文件，超过 180 份自动清理最早的
- 整段历史逻辑包在 `try/catch` 里，**历史读写失败绝不影响看板其余部分的生成**
- 目录已加入 `.gitignore`，不会弄脏工作区、不会在切分支时冲突
- 没有新增任何依赖

已经记录的指标：任务完成数、接口总数 / 已上线 / 未上线、未完成待办数、
分支总数与未合并数、方案分布（进行中/待上线/规划中/已完成）、以及每个模块单独的
任务完成数与接口数。**要加新指标时，改 `snapshot()` 一个函数即可**，
旧快照缺字段会被当成 0，不会报错。

## 五、判定口径（重要）

这些规则决定了看板怎么下结论，改代码前请先读：

**1. 「上线」的定义**
一个接口算「已上线」，当且仅当它在 `master` 分支的控制器源码里存在（用 `git show master:<控制器>` 逐个比对）。
**`master` 是生产的唯一真相**——因为 `deploy/nas` 只部署 master。

**2. 增删改查的归类**
- 查 = `GET`
- 删 = `DELETE`
- 改 = `PUT` / `PATCH`
- 增 = `POST` 到资源根路径（如 `POST /api/orders`）
- 业务动作 = `POST` 到子路径（如 `/orders/{id}/deliver`、`/confirm-payment`）

订单这类业务「业务动作」比标准 CRUD 更重要，所以单列一列而不是硬塞进增删改查。

**3. 模块判定**
| 判定 | 条件 |
|------|------|
| 已在 master | 该模块全部控制器都在 master 上 |
| 只在分支 | 有控制器只在分支上存在 |
| 无代码证据 | 控制器在任何分支上都不存在 |

**4. 方案状态（规划与在途）**
不是照抄文档写的状态，而是用证据反推：
- **已完成**：引用的任务全完成，且引用的迁移都已上线
- **待上线**：引用的任务全完成，但迁移未上线或分支未合并 ← 本项目最典型的状态
- **进行中**：部分任务完成，或关联分支有未合并提交
- **规划中**：任务全未开始，或文档声明暂缓

若证据与文档声明冲突，卡片上会挂「声明与证据不一致」的红标。
若任务勾选是 0 但分支已有大量提交，会明确写出「03-TASKS.md 的勾选落后于代码」。

**5. 前端覆盖率的口径边界**
只统计 `blade-admin/src/api/*.ts` 和 `blade-mobile/src/api/*.ts` 里的调用。
**如果页面绕过 api 层直接发请求，会被算成「没调用」。** 新增页面时注意保持 api 层收口。

## 六、询问 AI

看板里的「询问 AI」按钮（模块详情、方案卡片、项目级各一个）会给你三样东西：

1. **复制 Prompt** → 粘到 DSH 对话框（<http://127.0.0.1:43120>）或 Codex
2. **复制命令行** → `cd <项目根> && dsh --profile headless "读取 outputs/ask/<模块>.md，按文件末尾列出的问题回答"`
3. **下载上下文 .md** → 一份自包含快照，可交给任何 AI

上下文包由生成器写入 `outputs/ask/`，内容包括：模块概况、逐资源增删改查、未上线接口清单、
已完成/未完成任务、相关规划方案、相关页面、最近提交，末尾附 4 个待答问题。
`outputs/ask/_project.md` 是项目级版本。

**它不做的事**：不猜测。包里只有事实，并明确要求 AI「快照里没有的信息就说没有」。

## 七、与 gen-status.mjs 的关系

| | `gen-status.mjs` | `gen-cockpit.mjs` |
|---|---|---|
| 数据源 | 只读 `03-TASKS.md` | git + 代码 + 文档 |
| 产物 | `docs/STATUS.md`、`outputs/status.html` | `outputs/cockpit.html`、`outputs/ask/` |
| 回答 | 文档口径的进度 | 生产可用性 + 文档与代码的差距 |

两者**不冲突**：STATUS.md 轻量、入库、给快速阅读用；全景台重、派生、用来查证。
CLAUDE.md 规则 8 要求两者都刷新。

## 八、已知边界（不要误读）

- **只看 master 是否包含某段代码，不验证运行时是否正常。** 已上线 ≠ 已验证。
- **前端覆盖率只到资源级**，不到「哪个页面调的」。
- **任务完成度仍来自人工勾选**，全景台只是把它和代码对照，并不会自动勾选。
- **进展页首次打开是空的**：只有一份快照时没法对比，下次打开才会有内容。
- **`outputs/cockpit.html`、`outputs/ask/`、`outputs/cockpit-history/` 都不入库**（`.gitignore` 已排除），因为它是完全派生的产物，
  入库会导致每次重建都弄脏工作区、并在切分支时产生冲突。需要分享时直接发文件或让对方重建。
