# 旧 ERP 全功能审计与测试操作清单

> 系统：`https://cnnew.qiyunji.com/main.html`  
> 审计日期：2026-09-01  
> 当前阶段：只读审计已覆盖全部菜单；T01、T02、T04、T05 及使用“御龙”的最小 T06-T10 闭环已完成，T03 因账套容量上限阻断  
> 操作边界：不得修改或删除系统内原有数据。后续获批后，只使用带统一测试标识的新建资料和新建单据。

## 1. 审计范围与证据等级

- **A：历史数据交叉验证**：同一单号已在业务单据、库存流水、资金流水或核销明细中互相对应。
- **B：页面与前端逻辑验证**：已读取页面字段、操作入口、状态字段及前端业务处理逻辑，但未执行写操作。
- **C：需要新增测试数据验证**：仅靠只读页面无法确认最终事务行为，必须创建隔离测试资料和测试单据。

只读审计阶段没有执行保存、审核、反审核、确认、删除、开票、分享、打印或设置变更。2026-09-02 经明确批准后执行了 T01-T05；只新增带统一测试标识的基础资料，未修改或删除原有资料，也未创建业务单据。

## 2. 系统业务主链路

```text
基础资料
  -> 预定/业务单据
  -> 审核过账
  -> 库存流水 + 应收应付
  -> 收付款/预收预付
  -> 核销关系
  -> 资金流水
  -> 经营与进销存报表
```

系统能力上区分“保存”和“审核”，也提供“保存并审核”。但当前账套已开启“自动审核”，因此新建业务单据一旦保存，就可能立刻完成过账并影响库存与资金账户。公共前端逻辑明确提示：审核、反审核及删除业务单据会操作商品库存和资金账户。

### 2.1 页面与接口组织方式

- 菜单中的多数业务 `main.html` 是直接开单页，`form.html` 是单据列表/报表页；基础资料的 `main.html` 则通常是列表并在抽屉或弹窗中新增。
- 主要业务模块遵循统一接口约定：`form_list` 查询列表、`info` 查看详情、`auditing` 审核/反审核、`del` 删除、`exports` 导出、`prints` 打印。
- 各模块只替换路径前缀，例如销售使用 `/index/sale/*`、进货使用 `/index/purchase/*`、盘点使用 `/index/room_check/*`。零售新版是例外，详情/审核/删除分别使用 `infos_new`、`auditing_new`、`del_new`。
- 审核与反审核共用同一模块的 `auditing` 地址，由动作参数决定方向；因此接替系统不能把“反审核”仅实现为前端状态改名，而应作为有依赖校验的逆向事务。

### 3.7 权限、输出配置与审计

#### 功能权限

- 权限以职员为主体配置，业务功能矩阵固定包含“新增、删除、修改、报表、审核”五类动作；每个业务模块可以全选，也可以逐动作授权。
- 权限对象覆盖进货预定、进货、进货退货、销售预定、销售、销售退货、零售、零售退货、积分兑换、调拨、其他出入库、组装拆卸、收付款、核销、其他收支和资金调拨。
- 另有非 CRUD 权限：库存查询、隐藏进货价格、数据报表、基础资料、客户、辅助资料、高级设置、禁止修改销售价、隐藏销售价格，以及首页六类统计模块的可见性。
- 新建职员需要登录账号、密码、所属门店和职员名称。页面提示新账号默认未授权全部功能；创建时可选“管理员”“销售员”“超级销售员”或单独设置权限。
- 销售员预设可开销售、销售退货、添加商品及查看库存，但不能看进货价；超级销售员在此基础上还可开进货单。

#### 数据范围权限

数据授权与功能权限独立，按职员分别限制：门店、客户、供应商、仓库、职员、资金账户和调拨仓库。每个维度支持多选及全选。接替系统必须同时通过“能否执行某动作”和“能看到/选择哪些数据”两层校验。

#### 打印、字段与日志

- 打印模板按业务类型保存模板名称、纸张类型、宽高、默认和停用状态；支持设计、复制设计、设为默认、停用及删除。
- 模板业务类型覆盖销售/采购及预定、双方退货、零售、积分、调拨、盘点、组装拆卸、其他出入库、收付款、资金调拨、标签和对账单。
- 页面还有“打印不显示弹窗”的全局开关；新系统应区分模板配置、预览和真正发送到打印机三个动作。
- 字段设置目前有 240 条记录，同一业务对报表、导出、详细导出、单据详情和打印模板使用不同表单标识，例如 `_form` 与 `_export`。字段顺序/可见性不能只保存在前端本地。
- 操作日志页面可见字段为所属门店、操作时间、操作内容、职员，支持按内容、用户和日期过滤。页面提供“清空”入口，但本次及后续测试均禁止使用。

### 3.8 商品辅助资料与定价模型

- 商品分类是支持父子层级的树；可在某分类下新增子分类，也支持拖拽移动。移动、批量删除和导入会改变共享分类树，测试不得操作原分类。
- 商品属性采用“属性组 + 属性选项”模型，选项支持逐个添加或按“一行一个”批量添加；商品启用属性后形成辅助属性组合。
- 单位和品牌都是独立基础资料，均包含名称、编号和备注。商品启用多单位前必须先选择基础单位，辅助单位应基于基础单位保存换算关系。
- 客户等级价提供最多十个等级槽位，每级包含客户等级名称、对应等级价名称、相对批发价的百分比和启用状态。客户关联等级，商品再维护各等级价格。
- 商品套餐是可销售的组合商品，包含条码、编号、必填分类、单位、规格、状态、批发价、零售价，以及多行组成商品、辅助属性、数量和组件价格。它与组装拆卸单是两个独立模型。
- 收支分类以名称、收入/支出类型和备注维护，是其他收入/支出的必选维度。

### 3.9 首页仪表盘与组织

- 首页今日指标包括销售毛利、销售额、销售笔数和资金入账，并显示昨日对比。
- 常用入口覆盖销售、进货、库存、商品、客户、供应商、应收和应付；另有可配置的常用功能快捷入口。
- 汇总信息显示客户、供应商、库存、库存预警和职员数量。
- 资产情况明确使用公式：总资产 = 账户余额 + 库存总额 + 应收欠款 - 应付欠款。
- 首页还包含数据概览、现金流趋势、新手向导、公告、多端下载与打印助手；各主要统计模块受独立首页权限控制。
- 门店是组织根维度，保存名称、编号、联系人、电话、地址、税号、开户银行、对公账户和备注；职员归属门店，业务单据和报表同时保留所属门店。

## 4. 已用历史数据确认的事务规则

1. **销售审核过账**：同一销售单号同时生成商品出库流水和销售收入资金流水。
2. **进货审核过账**：同一进货单号按商品及属性生成入库流水；有付款时生成进货支出。
3. **零金额进货仍可产生库存，但不是免费采购**：业务方为避免工厂人员看到出厂价和销售价，主动把商品价格和单据金额录为 0，只使用单据驱动库存；库存数量与财务金额必须解耦，旧账零金额不得解释为真实成交价。
4. **调拨双边平衡**：同一调拨单按商品维度生成等量的调出与调入流水。
5. **收款逐单核销**：收款单保存原单欠款、已核销、未核销和本次核销。
6. **反审核有依赖检查**：存在收付款或核销关联时，系统阻止直接反审核，并引导先解除关联。
7. **删除属于回滚事务**：业务单据删除会操作库存和资金；不能实现成普通软删除状态切换。
8. **盘盈盘亏派生单据**：盘盈进入其他入库，盘亏进入其他出库，派生单据处于已审核状态。
9. **预定存在转换余额**：销售/进货预定分别统计预定、已转及剩余数量和金额。
10. **报表基于统一业务分类**：商品收发汇总明确区分进货、销售、退货、零售、调拨、盘点、组装拆卸及其他出入库。

## 4.1 当前账套关键开关

以下内容来自系统参数页面的只读值：

| 参数 | 当前值 | 对测试与接替设计的影响 |

## 4.2 保存时的通用校验与数据结构

只读脚本确认所有主要业务单据共用同一套提交框架：

- 单据日期、单据编号、制单人和至少一条明细为通用必填项。
- 明细以商品、仓库、调入仓库等标识组成数组提交；组装拆卸可提交第二组明细。
- 销售单必须有客户和结算账户，本单应收必须为合法非负金额。
- 进货单必须有供应商和结算账户，本次付款不得大于本单应付。
- 销售单保存来源字段 `source`，可关联销售预定；进货单同样可关联进货预定。
- 积分兑换要求实收积分不大于实际积分，且不能超过客户现有积分。
- 零售退货要求实退金额不大于单据金额，并单独校验退款金额和扣除积分。
- 盘点启用串码时，会强制校验盘点串码数量与实际数量一致。
- 编辑已有关联收付款或核销的单据时，后端会阻止直接保存并要求先解除关联。

## 4.3 单据状态机与转换关系

| 对象 | 只读确认的状态/动作 | 接替实现要点 |
|---|---|---|
| 通用业务单据 | 未审核、已审核；审核与反审核共用动作接口 | 状态变化必须和库存、资金、往来账事务一致 |
| 销售/进货结算 | 未处理、部分核销、已核销、强制核销 | 单据金额、已收/已付、优惠、核销额和剩余欠款不能合并成单一状态字段 |
| 销售/进货开票 | `0` 无需发票、`1` 未开票、`2` 已开票 | 单笔开票可写发票号和备注；撤销开票从 2 回到 1 |
| 盘点 | 盘盈/盘亏/平衡 + 独立确认状态 | 审核过账与“已盘点标记”是两个维度；确认仅标记本单商品，重置会把库存商品改为未盘点 |
| 销售预定 | 转销售、查看转销售记录；页面逻辑还提供转进货预定 | 保存正式销售单时保留预定来源 ID，并计算已转/未转数量 |
| 进货预定 | 转进货、查看转进货记录、转销售预定 | 保存正式进货单时保留预定来源 ID，并计算已转/未转数量 |

预定转换使用专门的带来源页面：销售预定转销售为 `/index/sale/infoBySor?sorId=...`，进货预定转进货为 `/index/purchase/infoByBor?borId=...`；跨类型转换分别使用 `/index/bor/infoBySor?sorId=...` 和 `/index/sor/infoByBor?borId=...`。这说明“来源单据 + 已转换数量 + 转换记录”是正式业务模型，不只是复制明细。

## 4.4 各类开单页的金额与库存语义

- 销售预定记录总计金额、定金、其他费用和结算账户；正式销售增加客户欠款、本单应收、本次收款、未收及本单欠款。
- 进货预定记录应付金额、定金、其他费用和结算账户；正式进货增加供应商欠款、本单应付、本次付款、未付及本单欠款。
- 销售退货与进货退货均可直接选择商品、仓库、数量、退货单价，并填写本单应退、本次退款和结算账户；开单页没有强制选择原销售/进货单的字段。是否允许无原单保存属于 C 级测试项。
- 调拨单同时指定出库仓库和入库仓库，每行只输入调拨数量，不输入价格；成本应从原库存层转移而不是由用户重新定价。
- 盘点行同时保存账面数量、实际数量、盈亏类型、进货价、盈亏数量和盈亏金额。
- 组装拆卸用两组明细表达：原商品清单负责消耗，新商品清单负责入库；支持倍数、模板和“一键获取成本”，原商品成本价为明确必填项。
- 收款/付款分别保存收付金额、优惠金额、核销金额和本次预收/预付。收款页提供手动核销与自动核销切换；当前付款页默认显示手动核销，自动行为需测试确认。
- 核销单由两组原单构成：一侧选择预收/预付，另一侧选择应收/应付，并提供“自动调节”分配本次核销金额。
- 其他收入必填收入类型、结算账户、金额，可选付款单位；其他支出必填支出类型、结算账户、金额，可选收款单位。
- 单笔开票会提交业务单 ID、目标开票状态、发票号和备注；批量开票只提交多个测试单 ID 和“已开票”状态，因此批量场景可能不要求逐单发票号，需用测试单确认。

4. 一张 2024 年销售预定仍有 100 件未转，属于陈旧承诺，必须人工处置。
5. 发票工作列表与销售主表的未开票数量不一致，需按单号对账。

因此新增 `ERP-DATA-001`：在任何生产迁移前输出价格可信边界、外部真实金额来源、空单位、未审核单、陈旧预定、开票差异和孤立来源关系清单，并要求业务逐类签字确认。迁移程序必须区分“可信库存事实”“待外部对账的金额”“未过账草稿”“仅归档记录”和“需人工处置例外”。

### 11.7 业务方对零金额原因的确认（2026-09-03）

业务方明确说明：旧 ERP 同时开放给工厂人员使用，但无法可靠屏蔽商品出厂价和销售价。为了保护价格隐私，后续把商品出厂价、销售价以及相关单据金额设置为 0，单据只用于登记商品数量和库存出入库，没有把旧 ERP 作为真实销售、采购结算或利润系统使用。

由此确定旧数据的可信等级：

| 数据字段 | 可信度 | 新系统处理 |
|---|---|---|
| 商品/SKU、颜色尺码、仓库 | 高 | 作为库存主数据和迁移匹配依据 |
| 单据日期、单号、数量、库存方向、制单人 | 高到中 | 作为库存历史和操作轨迹迁移，仍需盘点来源对账 |
| 出厂价、进货价、销售价、单据金额、成本、毛利 | 低 | 默认不迁移为财务事实；只有与外部可信账本对账后的记录才能进入正式金额模型 |
| 已付款、应收、应付、资金余额 | 低 | 状态可能只是零金额下的系统自动结果，不代表真实结算完成 |
| 盘点、盘盈亏、其他出入库 | 高 | 旧系统的主要使用价值，迁移时保留来源和数量链 |

“金额为 0”必须保留为原始录入值或迁移备注，不能在新系统中解释成真实零价、全额付款、零成本或 100% 毛利。若外部账本无法提供可靠价格，新系统只迁移库存数量历史，并从切换日开始建立新的价格、成本和财务真相。
