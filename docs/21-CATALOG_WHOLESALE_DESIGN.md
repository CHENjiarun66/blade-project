# 客户选款、批发清单与草稿接入

> 现行代码契约，2026-11-03。基于用户已确认的静态 v4.1；代码与本机联调完成，生产仍为旧选款页。真机和发布见 `TEST-CATALOG-DEVICE-001`、`OPS-CATALOG-001`。

## 业务边界

入口 `/catalog` 继续复用登录、`data:catalog:view` 和租户数据范围。选款页从实际商品、图片绑定和库存标记读取资料，不包含演示商品、预设报价、固定图片或模拟库存。客户选款只形成待店员核对的草稿，不执行正式订单、收款或库存操作。

每个款号一行：颜色说明（混色、色数、具体颜色均可）、整款数量、本次客户单价、只读金额。色数不乘数量；不强制零售式逐 SKU 配货。单价逐单可改，不修改商品主数据。数量或价格留空代表待补充，明确输入 0 元代表零价，两者不同。前端用 BigInt 分单位计算，后端用 BigDecimal 重新计算，不采信客户端金额。

浏览中点爱心加入清单，也可打开详情填写后保存。保存后回到原列表位置，保留筛选和同款照片，不自动跳入清单。清单支持直接输款号、改单、移除/撤销、全选和仅移交勾选行；“只看已选”包含本机完整清单，不受当前服务器分页影响。页面保留“新一轮选款”，确认后清空本次报价和已选项。

清单按租户/用户保存在本机，刷新恢复，登出清除；未移交前不跨设备同步，也不当作已开单记录。失败和权限拒绝保留当前清单；清单最多 200 款。

## 主屏幕启动比例与底部安全区（2026-11-03）

用户 iOS16.1.1 主屏幕新截图显示启动放大/右侧裁切，详情底部导航后还有两条空白。页面没有对应的两个占位组件；代码原先跳过非1倍缩放，也把主屏幕布局/可视高度最大值当作可用高度。当前改为：

- 状态栏启动样式 `default`，由系统在页面之外保留状态栏；viewport继续device-width、initial-scale=1、viewport-fit=cover。根文档在选款路由期间锁定外层滚动，页面固定填满实际可视视口；离开路由移除自己添加的宿主class。
- 手机根底padding为0，导航总高52px+safe-bottom，安全区与导航同一白色背景；不额外预留顶部状态栏高度。iPad导航隐藏，仍由根布局留安全区。不把系统home indicator安全区删掉来假装消除空白。

## 接口适配

旧读取路由和返回 DTO 不变：

| 接口 | 本轮适配 |
|---|---|
| `GET /api/catalog/products` | 新增可选 `productCode` 精确款号（≤100 字）、`productIds` 逗号分隔正整数 ID（≤100）；沿用原搜索/分类/颜色/尺码/现货/有图分页 |
| `GET /api/catalog/products/{id}` | 复用详情读取，刷新后再保存；接口失败保留已加载款式，移交时强制重新核对 |
| `GET /api/catalog/filters` | 复用真实筛选项，不硬编码分类 |
| `GET /api/outlets/options` | 复用可访问档口与默认档口；以服务端再次授权为准 |
| `POST /api/catalog/handoffs` | 新增移交适配层，要求 `data:catalog:view` + `btn:order:create`，创建现有订单草稿 |

“有图”筛选与实际相册一致，支持仅图集/仅 SKU 图片，不把已失效文件当有图；子查询显式保持相同租户，有效商品和 SKU 范围。用户于本轮明确选择客户可看可用件数：读取 DTO 新增商品/SKU `availableQty`，不返回价格、成本、供应商、原始库量、仓库或预留明细。

移交示例：

```json
{
  "requestId": "dfe5b940-5e89-43b7-b365-485b3379ed80",
  "sourceOutletId": 1,
  "items": [
    {"productId": 25, "colorNote": "混色（3色）", "quantity": 120, "unitPrice": "28.00"}
  ]
}
```

颜色说明最多 100 字；每款只能出现一次。数量可 null，否则为整数 1–999999（小数不得被 Jackson 截断）；单价可 null，否则非负、最多 6 位整数/2 位小数。已填金额合计不得超过现有 `decimal(12,2)` 范围 9999999999.99，超过时提示拆分或调整。

成功响应 `data` 仅包含 `draftId`、`reference`、`alreadyExists`。同一有效载荷重试沿用本机保存的 UUID；草稿通过 `CATALOG-<UUID>` 及现有租户/创建者/档口规则防重复。重试不覆盖店员已改的草稿。改变清单内容后移交会生成新的请求 ID 和独立草稿，原草稿继续存在；店员后续改单使用草稿入口。

服务端先检查租户与可用档口，再核对全部商品；不可用/跨租户商品拒绝，写入前失败不产生半张草稿。前端每次打开清单/移交前刷新商品状态，已下架行显式提示。HTTP 403 只提示无权，不当作登录失效清空报价；未认证请求统一返回 HTTP 401，保留既有认证续期逻辑；真实权限拒绝继续使用 403。

## 与店员草稿的字段对应

| 选款字段 | 现有草稿字段 |
|---|---|
| 服务端商品 ID、款号、名称 | `productId/rawProductCode/rawDescription` |
| 颜色说明 | `rawColor`（新增可编辑列，保存/刷新保留） |
| 整款数量 | `quantity/rawQuantity` |
| 本次单价 | `salePrice/rawSalePrice` |
| 数量 × 单价 | `paperAmount/rawAmount`（选款原金额） |
| 请求 UUID | `externalRefNo=CATALOG-<UUID>` |
| 选款单号 | `sourceBatchNo=XK-yyyyMMdd`、`sourceOrderNo=XK-<24位UUID>` |

适配层不猜测混色款的具体 SKU，不预先分摊颜色/尺码，不填纸单最终总额。店员在原草稿页面选择客户和履约规格、核对报价后才走既有确认开单流程；已有安全整款占位匹配逻辑保留。草稿新增来源提示并隐藏空原图面板，其他纸单/Agent 草稿行为不变。无新增 migration，不改正式订单和库存契约。
