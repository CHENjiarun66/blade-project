# 移动端 PWA 开发计划

> 记录移动端从设计到实现的完整流程。

---

## 一、目标

开发一个 **PWA（渐进式 Web App）** 形态的移动端应用，支持 iPhone、iPad、Android，通过 Safari/Chrome "添加到主屏幕"安装，接近原生 App 体验。

**核心约束**：
- 不依赖苹果软件认证
- 纯 AI 开发（开发者不打代码）
- 支持 iPad 响应式布局

---

## 二、技术栈

| 层级 | 选择 |
|------|------|
| 框架 | Vue 3.4+ (Composition API) |
| 构建工具 | Vite 5 |
| 语言 | TypeScript 5 |
| UI 组件库 | Vuetify 3 |
| 状态管理 | Pinia |
| 路由 | Vue Router 4 |
| PWA | vite-plugin-pwa |

---

## 三、功能优先级

| 优先级 | 系统 | 核心功能 |
|--------|------|---------|
| P0 | 订单系统 | 订单列表、新建订单、订单详情、状态变更 |
| P1 | 库存系统 | 库存查询、入库/出库、批量操作、扫码 |
| P2 | 看板系统 | 统计图表、实时数据刷新 |

---

## 四、开发流程

```
Step 1: Stitch 设计 UI
Step 2: Gemini 生成静态 .vue 文件
Step 3: Claude Code 接手，初始化项目 + 对接后端
Step 4: PWA 打包 + iOS Safari 添加到桌面
```

## 五、首页和导航架构

### 5.1 iPhone 布局

```
┌─────────────────────────────────────┐
│  [Logo]  Blade    [通知] [头像]    │  ← 顶部栏（固定）
├─────────────────────────────────────┤
│         内容区域（订单列表）          │
├─────────────────────────────────────┤
│  📦订单   📊库存   📋看板   ⚙️设置  │  ← 底部 Tab
└─────────────────────────────────────┘
```

### 5.2 iPad 布局（横屏，Master-Detail）

左侧边栏 + 右侧 Master-Detail，不浪费横向空间。

## 六、UX 设计原则

> "员工端 App 的敌人是'复杂'，不是'丑'。"

### 6.1 场景优先级

| 优先级 | 场景 | 设计要点 |
|--------|------|----------|
| P0 | 消息通知 / 任务推送 | 强提醒、即时响应、一触即达 |
| P0 | 审批流 | 极简操作路径、明确状态反馈 |
| P1 | 考勤打卡 | 地理位置验证、离线容错 |
| P2 | 数据查询 | 信息密度适中、支持快速筛选 |

### 6.2 员工端专项

- **批量操作优先**："批量发货"、"批量入库"比逐个操作重要
- **状态高亮**：订单状态用颜色区分，一眼扫过
- **扫码入口显眼**：员工高频用扫码枪/相机
- **快捷手势**：左滑删除、右滑标记

## 七、PWA 配置

### 7.1 manifest.json 必须字段

```json
{
  "name": "Blade 移动端",
  "short_name": "Blade",
  "display": "standalone",
  "orientation": "portrait",
  "start_url": "/"
}
```

### 7.2 Service Worker

- 必须注册 Service Worker
- 必须配置离线缓存策略
- 必须处理更新逻辑

---

## 八、iPad 适配

| 维度 | iPhone | iPad |
|------|--------|------|
| 布局策略 | 单列优先 | 多列/Master-Detail |
| 导航 | 底部 Tab | 侧边栏 + 底部 Tab |
| 触控区域 | 最小 44x44pt | 最小 50x50pt |
