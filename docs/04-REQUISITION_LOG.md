### [2026-03-21] 需求 #002 - 后端是否迁移

**提出者**：用户

**需求描述**：
- SpringBlade 每次启动都有鉴权和网关问题
- 文档不详细，AI 开发不友好
- 是否要迁移框架？

**AI 分析**：
- SpringBlade 的问题不是框架本身，是配置管理和文档缺失
- 但对纯 AI 开发模式，持续成本高
- SpringBoot 3 + MyBatis-Plus 多租户插件可完全复现功能
- 代码量少 4/5，AI 开发效率提升 3-5 倍

**结果**：✅ 采纳

**决策**：迁移到 Spring Boot 3 单体架构

**同步到 PRD**：已同步到 02-PRD.md 技术栈部分

### [2026-03-21] 需求 #004 - 多租户方案

**提出者**：AI（主动提出）

**需求描述**：
SpringBlade 的多租户是手动拼接 tenant_id，容易遗漏导致数据串租户。迁移后采用 MyBatis-Plus TenantLineInnerInterceptor 自动处理。

**AI 分析**：
- 手动拼接的致命问题：容易遗漏，安全隐患
- TenantLineInnerInterceptor 配置即生效，零代码改动
- 避免开发者忘记加租户条件

**结果**：✅ 采纳

**备注**：这是 AI 主动提出的决策，已记录到 02-PRD.md 多租户设计部分

### [2026-05-22] 需求 #006 - 外部 AI Agent 对接

**提出者**：用户

**需求描述**：
- 希望 BladeProject 对接 AI Agent，参考外部 Agent 架构设计稿筛选可复用方案。
- Agent 重点帮助判断款式趋势：哪些款持续向好，哪些款不建议继续做。
- Agent 需要基于客户订单和日期定时提醒需要跟进的客户。
- 后续希望接入 WhatsApp 信息，让 Agent 结合聊天上下文与系统数据分析客户状态。
- 需要支持月度、季度、年度经营分析和建议。
- 用户认可继续扩展 Agent 能力，未想到的经营场景由 AI 帮助补充规划。

**AI 分析**：
- 当前系统已经具备看板、经营分析、库存预警、客户订单日期和沉默客户等“答案型”能力，可作为 Agent Gateway 的底座。
- BladeProject 已锁定 MySQL、Redis、多租户、SKU + 仓库库存、订单配货与权限模型，不能直接照搬参考文档的数据库表和接口草案。
- Agent 接入要先守住租户隔离、数据权限和审计边界，第一期不应开放泛化写操作或后端自然语言查询。
- 除用户已提出方向外，Agent 还适合规划颜色尺码结构、库存取舍、客户流失风险、订单异常、利润解释、沟通反馈、异常检测和经营记忆等能力。

**方案建议**：
- 新增只读 Agent Gateway v1，第一期提供款式趋势、颜色尺码结构、客户跟进/风险、库存建议事实、周期经营报告数据包和跨模块搜索。
- Agent 使用独立凭证，绑定租户与 scope，毛利/成本数据需单独授权。
- WhatsApp 接入先作为第二阶段方案验证，先锁定合规接入、客户映射、权限、保留和脱敏策略。
- 订单运营异常、利润解释、WhatsApp 反馈分析、经营记忆等能力写入后续路线，按事件日志、毛利权限和外部数据接入成熟度排序。
- 后续在统一业务事件日志基础上再扩展变更订阅和窄范围 Agent 写动作。

**结果**：✅ 采纳

**同步到 PRD**：已同步到 `02-PRD.md` Agent 对接章节、`03-TASKS.md` Agent 任务组和 `10-AGENT_INTEGRATION_DESIGN.md`
