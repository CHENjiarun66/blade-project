### [2026-03-21] 需求 #001 - 移动端 PWA 开发框架选择

**提出者**：用户

**需求描述**：
- 移动端要用 Web 方式打开（PWA），不被苹果软件认证卡住

- Gemini 生成静态 Vue 组件后，Claude Code 对接
- 确定了 Stitch → Gemini → Claude Code 工作流

**结果**：✅ 采纳

**同步到 PRD**：已同步到 02-PRD.md 技术栈部分

### [2026-03-21] 需求 #002 - 后端是否迁移

**提出者**：用户

**需求描述**：
- SpringBlade 每次启动都有鉴权和网关问题
- 文档不详细，AI 开发不友好
- 是否要迁移框架？

**AI 分析**：
- SpringBlade 的问题不是框架本身，是配置管理和文档缺失
- 但对纯 AI 开发模式，持续成本高
- SpringBoot 3 + MyBatis-Plus 多租户插件可完全复现功能
- 代码量少 4/5，AI 开发效率提升 3-5 倍

**结果**：✅ 采纳

**决策**：迁移到 Spring Boot 3 单体架构

**同步到 PRD**：已同步到 02-PRD.md 技术栈部分

### [2026-03-21] 需求 #003 - 功能优先级确认

**提出者**：用户

### [2026-03-21] 需求 #004 - 多租户方案

**提出者**：AI（主动提出）

**需求描述**：
SpringBlade 的多租户是手动拼接 tenant_id，容易遗漏导致数据串租户。迁移后采用 MyBatis-Plus TenantLineInnerInterceptor 自动处理。

**AI 分析**：
- 手动拼接的致命问题：容易遗漏，安全隐患
- TenantLineInnerInterceptor 配置即生效，零代码改动
- 避免开发者忘记加租户条件

**结果**：✅ 采纳

**备注**：这是 AI 主动提出的决策，已记录到 02-PRD.md 多租户设计部分

### [2026-03-21] 需求 #005 - AI 开发规则

**提出者**：用户

**需求描述**：
- 有一个地方专门和 AI 讨论需求
- 一个文档给 AI 看，作为开发依据
- 任何新 AI 来了都能快速接手，不浪费时间
- 严格遵守开发规则，避免换 AI 后出现 bug

**AI 分析****：
- 设计三级文档结构：需求讨论区 → PRD → 任务清单
- PRD 是唯一开发依据，AI 自主执行
- 任务清单是 AI 驱动的，AI 自己领任务、自己更新状态
- 交接时必须同步文档

**结果**：✅ 采纳

**同步到 PRD**：已同步到 03-TASKS.md 任务领取规则部分
